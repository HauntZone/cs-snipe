# cs-snipe — CS2 准星切换器（零 VAC 风险）

极简 Windows 单文件程序：CS2 对局内随时切换 3 套准星配置，一键抓取当前游戏准星存入存储槽。纯 C + Win32 API，无第三方依赖，静态链接单 exe。

## 为什么零 VAC 风险

程序**全程不接触游戏进程**：不读写内存、不注入、不钩子、不模拟输入、不联网。它只做三件事：读写文本配置文件、读 Steam 注册表键、打开资源管理器。

对局内切换由游戏引擎自己的控制台系统完成：autoexec 中把按键绑定到 `exec cs-snipeN`，而 `cl_crosshair*` 是非作弊保护变量，对局内即时生效。这与用记事本手动编辑 autoexec 完全等价——Valve 明确允许的方式。抓取同理：读的是游戏自己落盘的配置文件，不是游戏内存。

## 快速开始

1. 双击 `cs-snipe.exe` 打开图形界面
2. 点「生成预设 + 应用绑定」（默认按键 F5 / F6 / F7）
3. 进 CS2 控制台执行一次 `exec autoexec`（或重启游戏）
4. 对局内按 F5 / F6 / F7 随时切换准星

## 图形界面

- **cfg 目录栏**：自动侦测，可手动修改；「打开目录」一键打开资源管理器
- **切换按键**：点击按键按钮进入「按键...」监听，按下任意键即绑定；**Esc** 取消、**Backspace** 设空（空 = 应用时解绑旧键）
- **三个存储槽**：显示预设名或抓取时间；「抓取当前准星」覆盖该槽
- **日志区**：每次操作的结果与提示

## 抓取当前游戏准星

1. 游戏内调好准星（或保持现状）
2. 控制台执行 `host_writeconfig`（引擎合法命令，即时落盘，无需 sv_cheats）
3. GUI 点某个槽的「抓取当前准星」，或命令行 `cs-snipe.exe -grab 槽号`
4. 之后对局内按对应切换键即可换回这套准星

## 命令行


| 命令                                 | 功能                                 |
| ------------------------------------ | ------------------------------------ |
| `cs-snipe.exe`                       | 图形界面                             |
| `cs-snipe.exe -cli`                  | 生成预设 + 应用绑定（默认 F5 F6 F7） |
| `cs-snipe.exe F8 F9 F10`             | 自定义按键（`none` = 该槽设空）      |
| `cs-snipe.exe -grab 2`               | 抓取当前游戏准星覆盖槽 2             |
| `cs-snipe.exe -open`                 | 打开侦测到的 cfg 目录                |
| `cs-snipe.exe -dir "D:\...\cfg" ...` | 手动指定 CS2 cfg 目录                |

## 存储与便携性

```
程序目录\
├─ cs-snipe.exe
├─ cs-snipe.ini       设置持久化：按键、CS2 目录
└─ cfg\            准星槽主存储（不存在自动创建）
   ├─ cs-snipe1.cfg   预设: 小绿十字 (静态)
   ├─ cs-snipe2.cfg   预设: 青色小点 (静态)
   └─ cs-snipe3.cfg   预设: 白色经典动态
```

应用 / 抓取时自动同步副本到 CS2 的 cfg 目录（`exec` 只能读游戏目录）。整个程序文件夹拷到别的机器即带走全部准星与设置。

已抓取的槽不会被「生成预设」覆盖；想让某槽恢复预设，删除对应 cfg 文件后重新应用。cfg 文件是纯文本，可用记事本直接改任何 `cl_crosshair*` 参数。

## 从源码编译

需要 MinGW-w64 gcc：

```bash
gcc -O2 -static -Wall -Wextra -o cs-snipe.exe cs-snipe.c -lshell32 -ladvapi32 -lgdi32
```

## 说明

- 改绑定后需在游戏内执行一次 `exec autoexec` 才生效
- 按键捕获支持字母 / 数字 / F1–F24 / 常用功能键；标点键不支持
- 没有任何第三方工具能对未来反作弊更新字面承诺「零风险」；本方案无攻击面，是理论上最安全的形态
